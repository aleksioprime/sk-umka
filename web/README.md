# Сайт мониторинга УМКИ

Откройте [мониторинг УМКИ](https://umka.technocrew.ru/) и войдите под своей учётной записью. Нажмите на устройство в таблице, чтобы посмотреть счётчики, историю сортировок и состояние камеры, модели и моторов.

В карточке есть два разных числа. **Предметов по счётчику устройства** — итог на самой плате. **Сортировок в журнале сервера** — сколько записей получил сервер. В журнале можно отфильтровать сортировки по периоду, виду отходов и ответу посетителя.

## Добавить устройство

Для регистрации нужна роль администратора. Сначала [установите программу и укажите `device_id` на плате](../deploy/README.md#4-подключить-плату-к-мониторингу).

1. На сайте нажмите **Добавить устройство**.
2. Введите ID из `~/app/umka.conf` и имя, по которому устройство будет видно в таблице.
3. Нажмите **Добавить**. После следующего сообщения с платы в карточке появится статус **Онлайн**. Обычно плата отправляет статус раз в минуту.

Если плата уже отправила сообщение, откройте **Журнал MQTT**. Введите её ID или выберите результат **Устройство не зарегистрировано**. У подходящего сообщения нажмите **Зарегистрировать**. ID подставится сам, останется ввести имя и нажать **Добавить**.

Плата появляется в списке после регистрации. Сообщения, полученные раньше, можно найти в журнале MQTT. Карточка и счётчики обновятся при получении новых данных.

## Изменить имя или убрать устройство

Откройте карточку устройства и выберите **Редактировать** или **Удалить**. Удаление скрывает устройство из таблицы и сводки. Если снова зарегистрировать тот же ID, история сортировок вернётся. Для нового названия достаточно изменить имя. MQTT-ID должен совпадать с настройкой платы.

## Посмотреть сообщения MQTT

MQTT — способ, которым плата отправляет данные серверу. Администратор может открыть журнал общей кнопкой над таблицей. Кнопка **Журнал MQTT** в карточке сразу подставит ID выбранного устройства.

В журнале есть фильтры по времени, ID, топику и результату обработки. Нажмите на строку, чтобы открыть содержимое сообщения. Например, топик `umka/umka-rpi5/status` содержит состояние платы, а сообщения в `umka/umka-rpi5/event` содержат сортировки и ответы.

## Запустить свою копию сайта

На компьютере с Docker и Docker Compose откройте терминал в папке проекта и создайте файл настроек:

```bash
cd web
cp .env.example .env
```

Откройте `.env`. Замените `change-me` одним и тем же паролем из букв и цифр в
`POSTGRES_PASSWORD` и `DATABASE_URL`. Вместо `change-me-to-a-long-random-string`
укажите отдельный длинный случайный секрет. Затем запустите сайт и создайте
пользователя:

```bash
docker compose up -d --build
docker compose exec backend python create_user.py admin --admin
```

Введите пароль для входа, когда программа попросит. Дождитесь ответа `{"ok":true}` на [localhost:8301/api/health](http://localhost:8301/api/health), затем откройте [сайт на компьютере](http://localhost:8301/) и войдите под пользователем `admin`.

Повторный запуск `create_user.py` для того же имени меняет пароль. Чтобы создать пользователя без прав администратора, уберите `--admin`. Остановить учебную копию можно командой `docker compose down` из папки `web`. Данные останутся в томах Docker.

<details>
<summary>Настройки рабочего сервера для администратора</summary>

- Устройства подключаются к `mqtt.skolhub.ru:8883` с TLS. Служба приёма сообщений на сервере использует адрес брокера из `MQTT_HOST` и порт из `MQTT_PORT`. Значения `MQTT_USERNAME` и `MQTT_PASSWORD` хранятся в настройках Coolify.
- Брокер передаёт сообщения службе `worker`, которая сохраняет их в PostgreSQL. Журнал читает топики из настройки `MQTT_TOPIC` (по умолчанию `umka/+/+`). Повтор отправленного события не дублирует сортировку.
- [GitHub Actions](../.github/workflows/web.yml) публикует сайт в Coolify при изменениях в `web/` на ветке `main`. Настройки запуска сервера находятся в [docker-compose.prod.yaml](docker-compose.prod.yaml).
- В Coolify можно создать пользователя командой `python create_user.py admin --admin` в терминале контейнера `backend`.

</details>

<details>
<summary>Адреса API для тех, кто меняет код</summary>

| Запрос | Что возвращает |
| --- | --- |
| `GET /api/health` | Доступность сайта и базы |
| `GET /api/devices` | Список зарегистрированных устройств |
| `GET /api/devices/{id}` | Состояние одного устройства |
| `GET /api/devices/{id}/events` | Последние события |
| `GET /api/devices/{id}/sorts` | Историю сортировок с фильтрами |
| `GET /api/summary` | Общую сводку |
| `GET /api/mqtt/messages` | Журнал MQTT для администратора |
| `GET /api/mqtt/messages/{id}` | Содержимое сообщения для администратора |

Кроме `/api/health`, эти запросы требуют входа. Администратор также может отправить `POST /api/devices`, `PATCH /api/devices/{id}` или `DELETE /api/devices/{id}` для управления реестром.

</details>
